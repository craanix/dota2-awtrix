# Dota 2 → AWTRIX-NG

Мост между Dota 2 и матрицей AWTRIX-NG. Показывает нотификацию «Принять», когда
найден матч, и во время игры выводит KDA, фарм и состояние базы.

[English](README_EN.md)

## Что делает

**Вне игры** — обычная ротация твоих приложений (часы, ISS, Klipper, погода).

**Нотификация о матче.** Как только Dota находит матч, на матрицу приходит
«Принять» — белым по зелёному, на 15 секунд. Если принять игру не успеешь,
подпись исчезнет сама.

**Во время игры** ротация переключается на экраны доты, остальные приложения
глушатся и возвращаются после матча:

| Экран | Показывает |
|---|---|
| `dota_stat` | `K/D/A` — убийства, смерти, помощь разными цветами |
| `dota_farm` | `LH/DN` и GPM — добито крипов, отжато, золото в минуту |
| `dota_base` | radiant сверху, dire снизу. Если GSI отдаёт HP построек — `54% 26%`, если нет — счёт `53:23` |
| `dota_dead` | Крупно тает секунды до респау. Заменяет `dota_stat`, пока ты мёртв |

По окончании матча прилетает `GG K/D/A`.

## Требования

- AWTRIX-NG с прошивкой ≥ 1.0 и API v1
- Dota 2
- Python 3.8+ и `requests`
- Windows (пути и автозапуск написаны под Windows)

## Установка

### 1. Конфиг GSI

Создай файл:

```
<Steam>\steamapps\common\dota 2 beta\game\dota\cfg\gamestate_integration\gamestate_integration_awtrix.cfg
```

С содержимым:

```cfg
"AWTRIX Dota2 Integration"
{
	"uri"        "http://localhost:42069"
	"timeout" 	"5.0"
	"buffer"  	"0.1"
	"throttle" 	"0.1"
	"heartbeat" 	"30.0"
	"data"
	{
		"provider"     "1"
		"map"          "1"
		"player"       "1"
		"hero"         "1"
		"abilities"    "1"
		"items"        "1"
		"draft"        "1"
		"wearables"    "1"
		"building"     "1"
	}
}
```

> **Важно.** GSI читает этот файл **при запуске клиента**. Если добавишь блок
> позже — перезапусти Dota, иначе он не заработает. После старта проверь в
> `bridge.log`: должно быть `building=yes`. Если `building=NO` — значит нужен
> перезапуск.

### 2. Логирование консоли Dota

Детект «матч найден» идёт через `console.log`, поэтому нужно включить лог:

Steam → ПКМ по Dota 2 → Свойства → Параметры запуска:

```
-console -condebug
```

Полностью закрой Dota перед запуском — иначе параметр не применится.

Если разрешить входящие соединения, разреши порт `42069`.

### 3. Запуск

```bash
pip install -r requirements.txt
python dota_awtrix.py
```

Скрипт крутится в фоне, лог пишется в `bridge.log`.

### 4. Автозапуск

Создай в `Автозагрузке` (`shell:startup`) файл `dota2-awtrix.bat`:

```bat
@echo off
cd /d C:\путь\к\проекту
start /min pythonw dota_awtrix.py
```

## Почему нужен console.log

Game State Integration **не умеет видеть лобби**. Полный список состояний
`DOTA_GameState` из `dota_shared_enums.proto` — это `INIT`,
`WAIT_FOR_PLAYERS_TO_LOAD`, `HERO_SELECTION`, `STRATEGY_TIME`, `PRE_GAME`,
`GAME_IN_PROGRESS`, `POST_GAME`, `DISCONNECT`, `TEAM_SHOWCASE`,
`CUSTOM_GAME_SETUP`, `WAIT_FOR_MAP_TO_LOAD`, `SCENARIO_SETUP`, `PLAYER_DRAFT`.
Все они существуют только **после** подключения к игровому серверу. Состояния
«матч найден, ждём принятия» среди них нет, блока лобби в GSI тоже нет.

Поэтому момент «нажми Принять» ловится по строке в `console.log`:

```
[GCClient] Recv msg 7170 (k_EMsgGCReadyUpStatus), 21 bytes
```

Она приходит в момент, когда лобби матча создан и игрок ждёт ответа.

### Ложные срабатывания

`k_EMsgGCReadyUpStatus` прилетает **в любом** лобби, включая practice и
кастомные игры. Поэтому скрипт смотрит в скользящее окно из 120 последних строк
лога: если рядом есть `PracticeLobby`, `CustomGame` или `Practice` — срабатывание
игнорируется.

В party-лобби, где кто-то жмёт «готов», нотификация тоже прилетит, и отличить
это от матчмейкинга по логу не выходит. Это осознанный размен: лучше лишний раз
уведомить, чем пропустить реальный матч. Если такой шум мешает — уменьши
`NOTIFY_COOLDOWN` или добавь свои маркеры в `IGNORE_IF_RECENT`.

## Настройки

В начале `dota_awtrix.py`:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `AWTRIX_IP` | `192.168.31.41` | адрес матрицы |
| `DOTA_GSI_PORT` | `42069` | порт, который слушает скрипт |
| `DOTA_LOG_PATH` | `<F:>\...\game\dota\console.log` | путь к логу Dota |
| `NOTIFY_COOLDOWN` | `30` | секунд между нотификациями о матче |
| `APP_DURATION_MS` | `5000` | сколько висит каждый экран |
| `DEBUG_CONSOLE` | `False` | `True` — писать весь лог Dota в `bridge.log` |
| `GSI_STALE_SEC` | `20` | если GSI молчит дольше — считаем матч конченным |

## Отладка

```bash
# что сейчас на матрице
python list_apps.py

# что происходило
Get-Content bridge.log -Tail 40
```

`bridge.log` пишет всё: смену ротации, найденные матчи, отклонённые ложные
срабатывания. Полезные строки:

- `*** MATCH DETECTED` — сработал детект
- `ignored (practice/custom)` — лобби отсеяно
- `rotation saved` / `rotation restored` — переключение ротации
- `gsi fields:` — какие поля реально приходят от Dota

При старте скрипт один раз сохраняет `gsi_sample.json` — сырой payload GSI.
Если что-то показывает нули, сначала загляни туда.

## Ограничения

- Детект «Принять» работает только с `-console -condebug`
- `console.log` Dota удаляет при выходе — это нормально, скрипт переоткроет файл
- Блок `building` требует перезапуска Dota после правки конфига
- Ротация восстанавливается по сохранённому списку: если руками переставишь
  приложения во время игры, после матча вернётся то, что было до
- Порт `42069` занят — скрипт не стартует, GSI молча не работает

## API AWTRIX-NG

Используются три маршрута:

| Метод | Путь | Зачем |
|---|---|---|
| `POST` | `/api/v1/notifications` | «Принять», «GO», «GG» |
| `PUT` | `/api/v1/apps/pushed/{name}` | экраны KDA / фарм / база / смерть |
| `PUT` | `/api/v1/apps/order` | переключение ротации |
| `DELETE` | `/api/v1/apps/{name}` | убрать экран |
